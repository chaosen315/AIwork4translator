## 发现项

### MAJOR R-001：README 的 API 配置说明与当前实现冲突
- 位置：`README.md` 的“配置 API”和“环境变量详解”章节
- 相关代码：`main.py` 通过 `load_dotenv("data/.env")` 读取配置；`modules/api_tool.py` 实际按 provider 使用 `KIMI_API_KEY`、`DEEPSEEK_API_KEY`、`GEMINI_API_KEY`、`OPENAI_API_KEY` 等专有变量
- 问题描述：README 仍以通用的 `API_KEY`、`BASE_URL`、`MODEL` 作为示例与变量说明，但当前实现不会读取这些通用变量用于主翻译流程。用户即便按 README 配置，仍可能在运行时收到“缺少 api_key”的错误。
- 风险：直接影响首次配置成功率，且错误表现会让用户误以为程序存在运行问题，而不是文档过期。
- 改进建议：README 应改为“provider 专有环境变量优先”的说明，并给出至少一组可直接运行的 `.env` 示例。

### MAJOR R-002：README 未说明“部分完成/失败段清单”这一新行为
- 位置：`README.md` 的“核心特性”“CLI 使用指南”
- 相关代码：`main.py` 会在段落级重试用尽后生成失败段清单；`modules/write_out_tool.py` 会在最终 Markdown 顶部写入“部分完成”摘要，并把 `failed_segments`、`translation_status` 回写到 `_intermediate.json`
- 问题描述：README 仍只笼统描述“异常恢复、断点续传、Ctrl+C 中断保护”，但没有说明新版在失败场景下的显式输出行为：哪些段失败、结果是否为 `partial`、如何解读失败清单。
- 风险：用户在看到输出文件顶部的 warning 区块或 `_intermediate.json` 中的 `failed_segments` 时，缺少解释，容易误把“部分完成”当成正常完成或导出异常。
- 改进建议：在 CLI 使用说明中新增“失败恢复与部分完成”小节，明确说明失败段清单、`translation_status`、以及重新补跑的预期流程。

### MAJOR R-003：README 未警示 `_intermediate.json` 预处理会覆盖同名中间文件
- 位置：`README.md` 的“导出文件”“导出与预览（脚本）”附近
- 相关代码：`modules/read_tool.py` 的 `read_and_process_structured_paragraphs_to_json()` 会固定输出到 `<base_name>_intermediate.json`
- 问题描述：README 将 `_intermediate.json` 描述为可重复导出的稳定输入，但没有提醒“重新对同一源文件做预处理，会覆盖同名中间文件，从而丢失原先的翻译进度现场”。
- 风险：用户在调试、复盘或重复预处理时，可能无意中覆盖保留现场，导致无法继续按旧现场排查。
- 改进建议：README 应明确区分“翻译中间蓝图”和“导出输入源”的关系，并提醒对重要 `_intermediate.json` 先备份再重新预处理。

### MINOR R-004：README 对“稳健分段/保守解析/fallback”没有可见说明
- 位置：`README.md` 的“核心特性”“翻译模式”
- 相关代码：`modules/read_tool.py` 已新增表格、HTML、代码围栏、容器块等受保护边界；`modules/translation_core.py` 已新增保守解析和定向 fallback
- 问题描述：README 仍只区分“结构化模式/非结构化模式”，没有说明结构化模式已加强为“尽量保住表格、HTML、代码围栏边界”，也未说明在高风险内容上会主动采用更保守的处理路径。
- 风险：用户无法预期为何某些段会带有“fallback/保守恢复”的提示，也无法据此判断结果质量边界。
- 改进建议：在“翻译模式”章节补一段“高风险结构处理策略”说明，强调系统优先保正文和结构边界，而不是强行补全术语与注释。

## README 修改指导

### 必改章节
- `配置 API`
  - 删除或弱化通用 `API_KEY/BASE_URL/MODEL` 示例
  - 改为 provider 专用配置示例，例如 `KIMI_API_KEY/KIMI_BASE_URL/KIMI_MODEL`
  - 说明不同 provider 读取不同变量，而不是统一读取一个 `API_KEY`

- `环境变量详解`
  - 将表格改成按 provider 分组
  - 至少覆盖：`KIMI_*`、`DEEPSEEK_*`、`GEMINI_*`、`OPENAI_*`
  - 保留 `Currency_Limit`、`Requests_Per_Minute`、`MAX_RETRIES`，并补充 `PARAGRAPH_MAX_RETRIES`

- `CLI 使用指南`
  - 新增“失败恢复与部分完成”小节
  - 说明：
    - 单段失败会自动重试
    - 达到上限后会进入失败段清单
    - 最终 Markdown 可能标记为“部分完成”
    - `_intermediate.json` 会写入 `failed_segments` 与 `translation_status`

- `翻译模式`
  - 在结构化模式下补充：
    - 表格、HTML 块、代码围栏、容器块会优先保边界
    - 高风险内容可能触发更保守的处理路径
    - 保守路径会优先保正文和结构，不保证术语/注释完整

- `导出文件`
  - 补充 `_intermediate.json` 的两种角色：
    - 翻译蓝图/恢复现场
    - 导出输入源
  - 明确提醒：重复预处理同一源文件会覆盖同名 `_intermediate.json`

### 推荐新增的小节
- `失败段与恢复排查`
  - 解释 `failed_segments`
  - 解释 `translation_status = completed / partial`
  - 建议用户如何基于失败段清单做二次补跑或人工复核

- `高风险内容说明`
  - 列出典型高风险内容：Markdown 表格、复杂 HTML、代码围栏、半截结构块
  - 说明这些内容上可能出现“保守解析输出”或“定向 fallback”提示
