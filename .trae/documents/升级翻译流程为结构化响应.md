## 总体目标

* 将翻译环节从非结构化字符串升级为结构化响应：`translation: str`、`notes: str`、`newterminology: List[Dict[str, str]]`

* 继续将正文写入 Markdown：`"\n\n---\n\n".join([translation, notes])`

* 将 `newterminology` 累积并写入 DataFrame，完成去重与合并后保存为新的术语表版本文件

## 影响范围

* 修改提示词：`data/.env`（参考 `data/.env:5-10`）

* 适配结构化输出：`modules/api_tool.py`

* 新增术语表工具：`modules/terminology_tool.py`

* 修改翻译流程：`main.py`

* 参考多供应商结构化输出规范：`api_structured_example.md`

* SiliconFlow JSON配置：使用 `data/.env:31-32` 的 `SILLICON_JSON_URL` 与 `SILLICON_JSON_MODEL`

## 结构化响应协议

* 定义统一模型（以 Pydantic 为技术方案）：

  * `class TranslationResponse(BaseModel):`

  * `translation: str`

  * `notes: str`

  * `newterminology: List[Dict[str, str, str]]`（字典键约定：`term`, `translation`， `reason`）

* 提供健壮的容错解析：

  * 优先使用供应商的 JSON/Structured Outputs；失败时从文本中提取首个 JSON 区块并校验字段

## 提示词改造（data/.env）

* 更新 `SYSTEM_PROMPT`（`data/.env:5-10`）：强调严格的结构化输出和字段含义，说明 Markdown 原文包含标题/列表/图片链接等元素，要求保留结构并按 schema 输出

* 更新 `BASE_PROMPT`：

  * 明确输出必须为 JSON，包含 `translation`、`notes`、`newterminology`

  * `notes` 用于“译注”列表文本；`translation` 为中文正文

  * `newterminology` 中的每项至少含 `{"term": 英文术语, "translation": 中文译名}`；如未给出译名，留空并在 `notes` 说明

* 针对 JSON Mode 供应商（如 DeepSeek、SiliconFlow 基础 JSON、Ark/Doubao `json_object`）：在 system 或 user 消息中包含“json”关键词

## 供应商适配方案（modules/api\_tool.py）

* 统一返回：各 Provider 的 `generate_completion` 返回 `(TranslationResponse, usage_tokens)`

* GPT（OpenAI）：

  * 使用 `response_format={"type": "json_schema", "json_schema": {"name": "translation_response", "strict": True, "schema": TranslationResponse.model_json_schema()}}`

* SiliconFlow：

  * 走 OpenAI SDK 兼容接口，`base_url` 使用 `SILLICON_JSON_URL`（`data/.env:31-32`），`model` 使用 `SILLICON_JSON_MODEL`

  * 首选 `json_schema` 模式；若模型不支持则降级 `json_object`

* DeepSeek：

  * 使用 `response_format={'type': 'json_object'}`，在提示中明确键名与结构

* Kimi（月之暗面）：

  * 使用 Partial Mode：assistant 预置 `"{"` 且 `partial=True`（参考 `api_structured_example.md`）

  * 拼接与解析为 JSON；添加容错 JSON 抽取与 schema 校验

* Gemini：

  * 使用 `response_mime_type: application/json` + `response_json_schema: TranslationResponse.model_json_schema()`（参考文档）

* Doubao（火山 Ark）：

  * 优先 `json_object`；若稳定可选 `json_schema`（beta，参考文档示例），通过 OpenAI 兼容接口 `base_url=DOUBAO_BASE_URL`

## LLMService 改造

* `create_prompt`: 保留专有术语注入逻辑；在末尾追加清晰的结构化输出指令和字段说明（与 `BASE_PROMPT` 一致）

* `test_api`: 构造 3 个结构化 case，校验能否成功返回含三字段的 JSON；失败时打印解析日志与最后一次错误

## 翻译流程改造（main.py）

* 位置：`main.py:132-171`

* 每段翻译：

  * 从 `llm_service.call_ai_model_api(prompt)` 获取 `TranslationResponse`

  * 生成正文字符串：`response_str = "\n\n---\n\n".join([translation, notes])`

  * 继续调用 `write_to_markdown(output_md_file, (response_str, meta_data), mode='structured' 或 'flat')`

  * 累积 `newterminology` 到 DataFrame（见下）

* 保持 token 计数与失败重试逻辑不变；结构化失败时降级为非结构化并记录告警

## 新增术语工具（modules/terminology\_tool.py）

* `load_glossary_df(path)`: 读取现有 CSV/XLSX 到 DataFrame；容忍不同列名（第二列视为译名）

* `merge_new_terms(df, newterminology)`: 追加新术语，基于 `term` 去重；若有冲突，保留已有译名并在 `notes` 标记冲突项数量

* `save_glossary_df(df, original_path)`: 在原目录生成 `glossary_<timestamp>.csv`，两列：`term, translation`

* 提供 `dict_to_df(newterminology)` 与 `normalize_keys(item)` 助手，保证键一致
